# PRD：uniHub 想法模块 v2 —— 灵感收件箱、标签筛选与整理流

> 建议文件路径：`.omo/plans/prd-thoughts-inbox-v2-detailed.md`  
> 适用项目：`zzicarus/uniHub`  
> 适用模块：`lib/src/plugins/thoughts/`  
> 版本：v2.0  
> 目标平台：Windows Desktop、Android Mobile，兼容 Flutter Web 的响应式布局预留  
> 优先级：P0 页面结构与筛选体验；P1 整理模式；P2 跨模块转化

---

## 1. 一句话目标

将当前「想法」页面从普通卡片列表升级为 **灵感收件箱**：支持快速记录、标签筛选、搜索过滤、置顶回看、待整理处理、随机回顾，并为后续“转待办 / 转笔记”预留稳定接口。

---

## 2. 当前问题

当前效果图显示，想法页面已经具备基本功能，但仍存在以下问题：

1. **快速记录区过重**  
   输入区占据首屏较大高度，但主要功能仍是快速记录，信息效率偏低。

2. **置顶信息重复**  
   主内容区有「置顶想法」，右侧栏也有「置顶想法」，同一信息出现两次。

3. **标签筛选不够显性**  
   虽然项目已有标签字段与标签筛选雏形，但页面上缺少明确的“按标签筛选”区域。

4. **卡片密度不足**  
   很短的想法占据较大卡片空间，导致用户无法快速扫描大量想法。

5. **右侧栏价值偏弱**  
   目前右侧主要是置顶、统计、热门标签。统计项如“总想法、本页展示、置顶数量”存在价值，但不足以推动用户整理和回顾。

6. **缺少整理流**  
   想法记录后没有明确的处理路径：保留、加标签、归档、转待办、转笔记等动作没有形成工作流。

## 3. 产品定位

「想法」模块定位为：

> 用于快速捕捉碎片念头，并通过标签、搜索、置顶、归档、整理、转化等能力，让想法从“临时记录”进入“可复用的个人知识与行动系统”。

核心路径：

```text
快速记录 → 自动/手动加标签 → 搜索/筛选 → 回看 → 整理 → 转待办/转笔记/归档
```

---

## 4. 设计原则

### 4.1 信息密度优先

想法页不是文章阅读页，而是高频扫视页。卡片应以摘要式展示为主，编辑在抽屉或详情页中完成。

### 4.2 快速捕捉优先

记录入口必须轻量，用户不应在记录前被分类、格式、标签等操作阻塞。

### 4.3 筛选条件必须显性

所有影响列表结果的条件都必须在页面上可见，包括：搜索词、状态筛选、标签筛选、归档筛选。

### 4.4 桌面端三栏，移动端单栏

桌面端利用右侧栏承载上下文辅助信息；移动端隐藏右侧栏，将辅助功能折叠到顶部筛选区或底部操作中。

### 4.5 第一阶段不强制改数据库

当前数据表已有 `content / tags / isPinned / archivedAt / imagePaths` 等字段。Phase 1 优先复用现有结构。

## 6. 快速记录 Composer

### 6.1 功能说明

快速记录区用于创建新想法。它应保持轻量，但支持富文本、图片、标签、置顶等能力。

### 6.2 桌面端默认形态

```text
快速记录想法
[ 今天有什么新想法？                                      ]

[添加标签] [图片] [置顶] [转为待办] [转为笔记]   Ctrl + Enter 快速保存   [记录想法]
```

### 6.3 边界条件

| 项目 | 规则 |
|---|---|
| Composer 最大宽度 | 跟随主内容区，最大 1080px |
| Composer 最小高度 | 160px |
| Composer 最大默认高度 | 不超过桌面端首屏高度的 30% |
| 输入区默认高度 | 96px - 120px |
| 输入区聚焦后高度 | 可扩展，但最高 240px，超过后内部滚动 |
| 记录按钮 | 无文本且无图片时禁用 |
| 保存快捷键 | `Ctrl + Enter` |
| 保存中状态 | 按钮文案显示“保存中”，按钮 disabled |
| 保存成功 | 清空正文、标签、图片、置顶状态，并刷新列表 |
| 保存失败 | 保留输入内容，显示错误提示 |
| 标签输入 | 最多显示一行，超出折叠为 `+N` |
| 待上传图片 | Composer 内最多展示 4 张缩略图，超过显示 `+N 张` |
| 图片缩略图尺寸 | 56px × 56px |
| 单条想法最大正文长度 | UI 不限制；建议内部软限制 20,000 字符，超过提示性能风险 |
| 空白内容 | trim 后为空且无图片时不能保存 |

### 6.4 标签输入边界

| 项目 | 规则 |
|---|---|
| 单条想法最多标签数 | 10 个 |
| Composer 内直接展示标签数 | 最多 5 个 |
| 超出 5 个 | 显示 `+N`，点击展开全部标签 |
| 标签最大长度 | 20 个字符 |
| 标签最小长度 | 1 个非空字符 |
| 标签允许字符 | 中文、英文、数字、短横线、下划线 |
| 标签存储格式 | Phase 1 继续使用逗号分隔字符串，例如 `产品,灵感` |
| UI 展示格式 | 统一显示 `#产品` |
| 输入 `#产品` | 存储为 `产品` |
| 重复标签 | 不允许重复，重复输入时忽略 |
| 大小写 | 英文标签默认大小写敏感；后续可统一 lowercase |
| 空格处理 | 标签首尾 trim；中间空格不建议，输入时提示或替换为短横线 |

### 6.5 图片边界

| 项目 | 规则 |
|---|---|
| 单条想法最多图片数 | 9 张 |
| Composer 默认展示 | 最多 4 张 |
| 超出展示 | 第 5 个位置显示 `+N` |
| 支持格式 | 跟随 image_picker 与平台能力，优先 jpg/png/webp |
| 单图建议大小 | 超过 10MB 提示可能影响性能 |
| 删除图片 | 从 Composer 删除时，同时从待保存图片列表移除 |
| 保存失败 | 不删除已选图片状态 |
| 图片路径 | 继续使用 `imagePaths` 字段存储 |

## 8. 标签筛选

### 8.1 功能说明

标签筛选是想法页的核心能力。它必须在 UI 中明确出现，而不是只依赖卡片标签点击。

### 8.2 主筛选区布局

```text
按标签筛选： #产品  #代码  #论文  #灵感  #生活  + 更多标签
已选标签： #产品  #灵感                                  清除筛选
```

### 8.3 主筛选区边界条件

| 项目 | 规则 |
|---|---|
| 标签筛选行数 | 默认最多 1 行 |
| 一行放不下 | 尾部显示 `+ 更多标签` |
| 默认展示数量 | 按使用频次最多展示 6 个；受宽度限制时减少 |
| 最少展示数量 | 至少展示 3 个常用标签，空间不足则横向滚动 |
| 更多标签入口 | 点击打开弹层 / popover / bottom sheet |
| 标签排序 | 使用次数 desc，其次名称 asc |
| 标签计数 | 统计当前归档状态下的全部想法，不受当前标签筛选影响 |
| 选中态 | 使用 primary 背景或深色填充 |
| 未选中态 | 使用浅色 chip |
| 禁用态 | 当前无标签时显示“暂无标签” |
| 清除筛选 | 清除所有已选标签，不清除搜索词和状态筛选 |

### 8.4 已选标签展示边界

| 项目 | 规则 |
|---|---|
| 已选标签区域 | 仅当存在已选标签时显示 |
| 已选标签最多展示 | 一行最多展示 5 个 |
| 超过 5 个 | 显示 `+N`，点击展开 |
| 单个已选标签 | 可点击 `×` 删除 |
| 清除筛选 | 一键删除所有已选标签 |
| 删除最后一个标签 | 已选标签区域自动隐藏 |

### 8.5 更多标签弹层

更多标签点击后展示完整标签列表。

#### 桌面端

使用 popover：

```text
更多标签
[搜索标签...]
#产品 8
#代码 6
#论文 4
#灵感 5
#生活 3
...
```

#### 移动端

使用 bottom sheet。

### 8.6 更多标签弹层边界条件

| 项目 | 桌面端 | 移动端 |
|---|---|---|
| 容器宽度 | 320px | 屏幕宽度 100% |
| 最大高度 | 420px | 屏幕高度 70% |
| 标签展示 | 垂直列表或 Wrap | 垂直列表 |
| 搜索标签 | 支持 | 支持 |
| 空结果 | 显示“没有找到标签” | 同左 |
| 点击标签 | 切换选中态，不关闭弹层 | 切换选中态，不关闭 bottom sheet |
| 完成按钮 | 可选 | 必须有“完成”按钮 |
| 清空按钮 | 有 | 有 |

### 8.7 单标签与多标签策略

Phase 1：单标签筛选。

```text
点击 #产品 → selectedTag = 产品
再次点击 #产品 → 清空 selectedTag
```

Phase 2：多标签筛选。

```text
selectedTags = {产品, 灵感}
```

多标签匹配模式：

| 模式 | 含义 | 默认 |
|---|---|---|
| OR | 包含任一已选标签 | 是 |
| AND | 必须包含全部已选标签 | 否，后续可加 |

### 8.8 标签筛选验收标准

- [ ] 页面上存在明确的“按标签筛选”区域。
- [ ] 默认最多显示一行标签。
- [ ] 超出一行时出现“更多标签”。
- [ ] 点击标签后主列表被过滤。
- [ ] 已选标签区展示当前标签。
- [ ] 可以单独移除某个已选标签。
- [ ] 可以一键清除标签筛选。
- [ ] 右侧常用标签点击后也能触发同一筛选状态。
- [ ] 空结果时显示明确空状态。
