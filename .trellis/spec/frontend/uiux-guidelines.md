# UI/UX 规范

> UniHub 前端体验规范。适用于页面、组件、弹窗、表单、导航与插件 UI。与 `component-guidelines.md` 配合使用：组件结构和 Token 看 component，体验状态和可访问性看本文。

---

## 设计目标

| 目标 | 要求 |
|------|------|
| 清晰 | 信息层级明确，主要动作一眼可见 |
| 可达 | 鼠标、触控、键盘、屏幕阅读器均可完成核心任务 |
| 一致 | 状态、文案、间距、反馈遵循统一模式 |
| 容错 | 空、加载、错误、重试状态不让用户迷路 |

---

## Accessibility / Semantics

- 所有仅图标按钮必须提供 `tooltip` 或 `Semantics(label: ...)`。
- 自定义可点击区域需要补齐 `Semantics(button: true, selected: ...)`，不要只依赖 `GestureDetector`。
- 列表项如代表可打开对象，应暴露可理解名称：标题 + 类型 + 关键状态，例如“打开想法：会议记录，已置顶”。
- 非文本状态（颜色、图标、徽章）必须有文字或语义补充，不能只靠颜色区分。
- 装饰性图标可使用 `ExcludeSemantics` 或不给交互语义，避免屏幕阅读器噪音。
- 动态错误/成功提示优先使用可见文本；临时提示使用 `AppToast.show` / `AppToast.undo`（位于 `lib/src/shared/widgets/app_toast.dart`），文案必须简短且可被重新触发。业务代码禁止直接 `SnackBar(content: Text(...))`。

---

## 键盘与焦点

- 桌面端所有可点击控件必须可通过 Tab 到达；禁用态控件可跳过焦点但要有原因说明。
- 自定义卡片/列表项使用 `InkWell`、`FocusableActionDetector` 或 Material 组件，保留焦点高亮。
- 焦点顺序应符合视觉顺序：导航 → 主内容 → 次级面板 → 浮层动作。
- 弹窗/菜单打开后焦点进入浮层，关闭后回到触发控件。
- 常见快捷键不得吞掉文本输入：输入框聚焦时不要拦截字符键。
- 破坏性动作需支持键盘确认/取消，并提供清晰焦点态。

## 交互状态

每个可交互组件至少考虑以下状态：

| 状态 | 视觉要求 | 实现建议 |
|------|----------|----------|
| default | 与周围层级区分明确 | `colorScheme.surface`、`outlineVariant`、Token 间距 |
| hover | 桌面端有轻微反馈 | Material `InkWell`、`hoverColor` 或 elevation/背景微变 |
| pressed | 点击瞬间可感知 | 保留 ripple/splash，不用不透明 `Container` 遮挡 |
| selected | 与 hover/pressed 不混淆 | `colorScheme.secondaryContainer` 或 `primaryContainer` + `on...` |
| disabled | 低强调但可读 | 使用 `onSurface.withValues(alpha: ...)`，避免纯灰硬编码 |
| focus | 键盘可见 | 使用 Material 默认 focus 或显式边框/高亮 |

禁止通过 `Container(color: ...)` 包住 `InkWell` 来遮挡 Material 交互反馈；需要有背景色时把颜色放在祖先 `Material` 上。

## Empty / Loading / Error / Retry

### Empty 空态

- 说明“当前没有什么”和“下一步可以做什么”。
- 如果有主操作，提供一个明确按钮；无操作时用简洁说明文字。
- 不使用假数据填充空态，不让用户误以为已有内容。

### Loading 加载态

- 首屏加载可用居中进度；局部刷新优先保留旧内容并显示轻量进度。
- 加载文案避免“马上完成”等不可保证承诺。
- 长列表加载不要造成布局跳动，可用稳定高度或骨架占位。

### Error 错误态

- 展示用户能理解的原因和下一步，不直接暴露技术栈异常。
- 可恢复错误必须提供“重试”；不可恢复错误给出返回/关闭路径。
- 错误状态要占据发生错误的区域，不用全局 Toast 代替页面错误。非阻塞轻提示使用 `AppToast.show`。

### Retry 重试

- 重试按钮应防重复点击：请求中进入 loading/disabled 状态。
- 重试失败保留错误说明，成功后清除错误态。

## 桌面 / 移动交互

| 场景 | 桌面端 | 移动端 |
|------|--------|--------|
| 导航 | 侧栏/多列布局，支持 hover/focus | 底部导航，入口数量克制 |
| 列表操作 | hover 可显示次级动作，右键菜单可选 | 主要动作显式展示，避免只依赖 hover |
| 弹窗 | 可使用居中 Dialog / 右侧面板 | 优先底部 Sheet 或全屏编辑 |
| 密度 | 可更紧凑但保持可读 | 保持触控尺寸和垂直间距 |
| 键盘 | Tab、Enter、Escape 可用 | 输入法和返回键体验优先 |

### 响应式布局三档策略

布局根据 `AppBreakpoints` 三档宽度切换，不使用平台硬编码：

| 档位 | 宽度 | 列数 | 触发场景 |
|------|------|------|----------|
| compact | `< 900px` | 1列（底部导航 + 全屏） | 手机竖屏、小屏平板 |
| medium | `900 - 1279px` | 2列（侧栏 + 内容） | 平板、小窗口桌面 |
| expanded | `>= 1280px` | 3列（侧栏 + 内容 + 右栏） | 全屏桌面 |

`AdaptiveLayout(mobile:, desktop:)` 负责 compact 与 medium+ 的切换，右栏在 expanded 时才显示。

### 主题预设切换

应用提供 6 套主题预设（Uni Blue / Paper / Forest / Sakura / Amber / Graphite），每套有独立亮色和暗色变体。用户在**设置页 > 外观**中可切换预设。切换应即时生效（通过 `themeSettingsProvider` 持久化偏好），无需重启应用。

**UX 要求**：
- 预设选择器显示预设名称和描述，如果可能显示缩略色板预览
- 切换后立即应用新预设，不影响已打开页面的滚动位置
- 亮/暗模式与系统设置联动，用户也可手动覆盖

## 触控尺寸与命中区域

- 主要可点击区域最小建议 `48×48`，紧凑桌面控件不得低于 `40×40`。
- 文本链接或小图标按钮如果视觉尺寸较小，需要用 Padding 扩大命中区域。
- 相邻破坏性动作和普通动作之间保留足够间距，避免误触。
- 列表项整行可点时，内部按钮点击区域不能与整行点击冲突。

---

## 文案规范

- 按钮使用动词短语：`新建想法`、`重试`、`保存`。
- 空态文案先说明状态，再给行动：`还没有想法。记录一个灵感开始吧。`
- 错误文案避免责备用户：用“暂时无法加载”而不是“你输入错误”。
- 破坏性动作明确对象：`删除这个标签` 优于 `删除`。
- 中英文混排按现有产品语言优先中文；技术名词可保留英文。

---

## 对比度与颜色

- Widget 层颜色优先来自 `Theme.of(context).colorScheme`。
- 文本和背景必须满足可读对比；不要在浅色容器上使用低透明度浅色文字。
- 状态不能只靠颜色表达，错误/成功/选中需有图标、文案或语义。
- 自定义装饰色只用于非关键信息；关键文字、按钮、错误使用 M3 语义色。
- 深色模式下必须复查 `surface`、`onSurface`、`outlineVariant` 的组合可读性。

---

## 表单反馈

- 必填项、格式要求和错误提示靠近输入项显示。
- 输入错误应说明如何修正，例如“请输入有效日期：YYYY-MM-DD”。
- 保存中按钮进入 loading 或 disabled 状态，避免重复提交。
- 保存成功后给出轻量反馈；如果页面内容已更新，可不额外弹窗。
- 离开含未保存更改的编辑页前，应提示保存/放弃。
- 长表单按逻辑分组，移动端避免过深嵌套和过小输入区域。

---

## Review Checklist

- [ ] 图标按钮有 tooltip / Semantics。
- [ ] 可交互组件具备 hover、pressed、focus、disabled、selected（如适用）状态。
- [ ] 空、加载、错误、重试状态完整且文案可执行。
- [ ] 桌面端键盘可达，移动端触控命中区域足够。
- [ ] 颜色使用 `colorScheme`，对比度在亮/暗主题下均可读。
- [ ] 表单错误靠近字段，保存/重试防重复触发。
